How the receipt rule stops duplicates

  1. The CRM prints or emails a tax receipt only when the payment type has Print receipt ticked and the payer is not a fiduciary.
  2. Otherwise the gift is saved with Receipt: issued by … (Givebutter, Benevity, the DAF) and the donor gets a thank-you note only.
  3. Each receipt gets a number the moment it is sent. A re-import, an edit or a re-run of the daily job never sends it again. A reprint is stamped Duplicate copy.
  4. The payment-type setting is the default. Staff can override it on a single gift, with a reason (for example, a donor asks for a CRY receipt for a Givebutter gift).

Where the CRM uses it

  • Donor address: city, county and state code fill in from the ZIP on every form, import and API pull.
  • QuickBooks: the class for website, Givebutter and monthly gifts is the donor's state code (CA, NY, TX…), taken from the ZIP master, not from what was typed. Donors outside the US get OC.
  • Donor matching: name + ZIP uses the 5-digit ZIP.
  • Tele-calling: call lists show the donor's local time and hide numbers outside calling hours in that time zone.
  • Action Centers: the Location Master lists the state codes each Action Center covers (proposed).

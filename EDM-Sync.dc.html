Never sent to a platform

  • Email status is not valid (ZeroBounce invalid, spamtrap, abuse, do_not_mail)
  • Unsubscribed or hard-bounced in either platform
  • Do-not-email (DNE) flag
  • Deceased or anonymous-only donors
  • Donor in the other platform's base (a donor is in exactly one platform)

  • Manual entry and tele-calling: checked live (single validate) before Save; an invalid email cannot be saved.
  • Imports and API pulls: the gift is never held for an email; the email is checked in the nightly batch.
  • An email is re-checked before its first push to a platform if its last check is over 6 months old.

What is stored

  • Campaign (Campaign Master): code, name, short name (= utm_campaign, unique, lower case, no spaces).
  • EDM mailer: mailer code (= utm_content, unique), campaign (FK), platform (CC / Zoho), platform campaign id, segment, send date, list snapshot. One campaign can have several mailers (invite, reminder, thank-you).
  • EDM results: one row per night for 30 days after the send (sent, delivered, opens, clicks, bounces, unsubscribes, spam) so trends show.
  • Email events: one row per donor for bounce, unsubscribe and spam only (donor FK, EDM send FK). Opens and clicks stay as totals.
  • The platform is used to send; the CRM is the record. Only summaries are shown on the campaign.

How a row is matched (in this order)

  1. CRY India donor ID already on a CRM donor (from an earlier GOPS file) → already in CRM.
  2. Email (lower case, trimmed) → already in CRM.
  3. Phone (10 digits, +1 and spaces removed) → already in CRM.
  4. Name + ZIP only → possible match: staff pick the donor or say it is new.
  5. No match → new donor, if the row has an email or a phone.
Rows whose country is not USA are rejected; the file should only have USA. The same CRY India ID twice in one file is loaded once.

What is saved

  • Existing donor: GOPS flag, CRY India donor ID, last GOPS file. Name, address, email and phone in the CRM are not overwritten; a different email or phone is shown for staff to accept.
  • New donor: name, email, phone, address, source = GOPS · CRY India, GOPS file (FK). Email checked by ZeroBounce and address by Smarty, as for any new donor; state from the ZIP master.
  • GOPS file record: file name, period (Q3 2026 or H1 2026), received date, counts per result. Every donor row links to it.
  • No gifts are created: GOPS donors gave to CRY India, not to CRY America.

WF-10 · Daily API sync: the order the Zoho jobs run
Each step is a scheduled Creator workflow (Deluge invokeUrl + Connection). Every record is stored by its source ID first, then matched; nothing posts to QuickBooks from a partial run.
1 · Givebutter API
GET /v1/transactions (updatedAfter = 3 days) · GET /v1/payouts (paid_at = yesterday)
2 · Authorize.net API ×2
getSettledBatchList (yesterday) → getTransactionList per batch → getTransactionDetails for ARB
3 · PayPal API
OAuth token → GET /v1/reporting/transactions (yesterday, status S, fields=all)
4 · WordPress pull (safety net)
Event Espresso /payments → /registrations (REG_count = 1) → /line_items · Charitable · form
Staging

One per Auth.net batch, PayPal day, Givebutter payout; net must equal the credit (WF-7)
